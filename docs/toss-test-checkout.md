# 토스페이먼츠 테스트 주문·결제

## 현재 구현 범위

2026-09-27: **테스트 전용** 연동입니다. 사용자가 발급한 테스트 키를 Cloudflare 비밀 설정에 등록하고 승인 Worker를 배포했습니다. 상점 실결제 계약은 아직 없으며 실제 토스 카드 인증까지의 종단 간 검증도 아직 하지 않았습니다. 자동 승인은 토스 API 응답을 모의하여 검사합니다.

상품 상세 → 테스트 주문서 → 서버 주문 생성 → 토스 공식 결제위젯 → 리다이렉트 → 서버 금액 검증/승인 → 결과 및 테스트 주문 내역을 구현했습니다. 원래 공통 헤더·푸터는 모든 화면에 유지됩니다.

공개 Pages 화면은 서버 주소 미설정 시 결제 버튼이 비활성화됩니다. 성공 URL로 이동했다는 이유로 결제 완료 처리하지 않습니다. 서버가 토스의 `DONE`, 주문번호, 결제키, 금액, 통화를 확인한 경우에만 완료 표시합니다.

## API 키 준비 후 로컬 실행

API 키 없는 주문 체험 기능은 삭제했습니다. 아래 절차는 토스 공식 테스트 환경에 연결하며 테스트 키가 필요합니다.

토스 개발자센터에서 **주문서형/결제위젯 테스트 클라이언트 키와 시크릿 키**를 준비합니다. 일반 결제창용 키와 혼용하지 마세요. 키를 채팅·GitHub·프런트엔드 코드에 넣지 않습니다.

`github-pages/`에서 `.env.server.example`을 `.env.server`로 복사한 뒤, 로컬 편집기로 아래 값을 입력합니다.

- `TOSS_CLIENT_KEY`: `test_gck_`로 시작하는 위젯 테스트 키.
- `TOSS_SECRET_KEY`: 같은 상점의 `test_gsk_`로 시작하는 서버 전용 키.
- `CHECKOUT_SITE_URL`: 기본 `http://127.0.0.1:5173/`. 끝에 `/` 포함.

키 입력 후 한 터미널에서 실행합니다. `toss:check`는 키 형식과 로컬 설정만 확인하며 토스 계정의 유효성을 검증하지 않습니다.

```sh
npm ci
npm run toss:check
npm run toss:dev
```

`toss:dev`는 화면과 승인 서버를 함께 시작하고 Ctrl+C로 함께 종료합니다. 화면 포트를 고정하여 결제 복귀 주소와 허용 Origin이 달라지는 것을 방지합니다. 이미 같은 포트를 쓰는 서버가 있으면 먼저 종료하세요. 시크릿 키는 화면 개발 서버의 환경변수에서 제외합니다. 별도로 실행하려면 기존 `npm run checkout:server`, `npm run dev`도 사용할 수 있습니다.

브라우저에서 `http://127.0.0.1:5173/#checkout/tote`로 이동합니다. 개발 서버 포트가 달라지면 `CHECKOUT_SITE_URL`도 일치시킵니다. 카드정보는 토스 결제창에서만 입력하며 이 앱은 수집하지 않습니다. 서버에 입력하는 실제 키 대신 문서에 하드코딩된 키를 사용하거나 가짜 성공 처리로 연결을 우회하지 않습니다.

## USD 상품 가격과 KRW 테스트 금액

상점의 상품 가격은 USD 표시를 유지합니다. 계약 전 기본 시험은 별도 **KRW 1,000원 × 수량**으로 이루어지며 화면에서도 별도의 시험 금액임을 표시합니다. USD 가격의 환율 환산이 아닙니다.

USD 테스트 상점 준비 후 `TOSS_TEST_CURRENCY=USD` 및 해당 상점의 테스트 키, `TOSS_PAYMENT_VARIANT_KEY`를 설정하면 서버 카탈로그의 USD 금액으로 시험하도록 구성했습니다. USD 해외카드는 별도 계약/MID/UI 설정이 필요합니다. 공식 해외결제 가이드와 SDK 일부 통화 설명에 차이가 있으므로 실제 USD 카드 지원 여부·variant는 토스 담당자와 해당 상점에서 확인해야 합니다. 미확인 상태에서 USD 결제가 가능하다고 표시하거나 KRW/USD를 자동 대체하지 않습니다. PayPal 배송정보 연동은 이번 범위에 포함하지 않습니다. 결제 UI는 즉시 승인되는 카드 테스트 수단으로 설정하세요. 가상계좌 등 입금 대기 상태를 완료 처리하지 않습니다.

## 서버 및 공개 사이트 연결

최신 배포 방식은 사용자 승인에 따라 Cloudflare Worker + SQLite Durable Object를 사용합니다. [Cloudflare 배포 안내](cloudflare-checkout.md)를 우선 참고하세요. 아래는 별도 Node.js 서버를 사용하는 대안입니다.

1. Node.js 22.13 이상(24 권장), 영구 디스크가 있는 별도 서버에서 이 저장소를 배치합니다. 서버는 `src/catalog.ts`도 읽으므로 `server/`만 복사하면 안 됩니다.
2. 서버에 `.env.server` 또는 환경변수를 설정합니다. `CHECKOUT_SITE_URL=https://jmwfdisk.github.io/k-market/`, 호스팅이 요구하면 `CHECKOUT_HOST=0.0.0.0`, `PORT`를 설정합니다.
3. `CHECKOUT_DB_PATH`를 영구 저장 경로로 설정하고 HTTPS를 제공합니다. 현재 SQLite 구현은 단일 서버 프로세스 운영을 전제로 합니다. 임시 디스크/함수 실행 환경은 적합하지 않습니다.
4. GitHub 저장소의 Actions **Variables**에 공개 API 주소 `VITE_CHECKOUT_API_URL=https://...`만 넣고 Pages 워크플로를 다시 실행합니다. 시크릿 키는 GitHub Pages 빌드에 넣지 않습니다.
5. 브라우저에서 주문 생성·취소·승인·재조회·모바일 복귀를 실제 테스트 키로 확인합니다.

서버/키가 준비되기 전에는 공개 API 주소를 추가하지 마세요. 최신 작업에서는 사용자 승인으로 Cloudflare Worker를 생성했으며 유료 플랜 업그레이드는 하지 않았습니다.

## 주문·결제 보장과 한계

- 금액은 서버의 상품 ID/수량/통화 설정으로 계산하고 클라이언트 가격은 사용하지 않습니다. USD는 정수 센트로 저장합니다.
- 비회원 주문은 무작위 접근 토큰으로 보호하며 서버에는 해시만 저장합니다. 조회/승인 모두 토큰이 필요합니다. 브라우저 `sessionStorage`의 토큰을 잃으면 본인 주문을 조회할 수 없습니다. 회원 주문 복구 기능은 별도 과제입니다.
- 생성 요청 ID를 재사용하면 같은 주문을 반환합니다. 승인은 DB 잠금과 고정 `Idempotency-Key`로 중복 요청을 제어합니다. 결제키는 한 주문에만 연결됩니다.
- 통신 실패/재시작 후에는 같은 결제키를 조회하고 동일한 멱등키로 처리합니다. 불확실한 승인 결과는 `VERIFYING`으로 유지하며 새 결제를 안내하지 않습니다. 확인 도중 프로세스가 종료되면 최대 60초 잠금 만료 후 재확인합니다.
- 주문 생성 후 30분이 지나면 새 승인을 요청하지 않습니다. 토스 인증 후 승인 제한 시간(공식 문서상 10분)도 적용됩니다.
- 주문 내역 화면은 현재 탭의 최근 20개 주문 및 마지막 서버 확인 상태입니다. 자동 웹훅, 환불/취소 반영, 실시간 주문 동기화는 구현하지 않았습니다.
- 테스트 키만 허용하고 라이브 키는 서버 시작 시 거부합니다. 실결제 전에는 견적/배송비·세금·재고·로그인·개인정보·웹훅·취소/환불·관리자 운영과 계약을 별도로 구현·검증해야 합니다.

## 검증

키 연결 후 정상 카드 인증 → 서버 승인 → `테스트 결제 완료`를 확인하고, 토스 개발자센터의 테스트 결제내역과 주문번호·금액을 대조합니다. 결제창 취소와 같은 주문의 결과 재조회도 확인합니다. 자동 검사의 모의 응답 통과만으로 이 절차를 완료했다고 판단하지 않습니다.

공식 환경 가이드에 따라 테스트 키의 승인에는 실제 출금이 없습니다. 간편결제 등 수단별 지원 범위는 상점/계약에 따라 다르므로 우선 카드로 확인합니다. 가상계좌 입금 처리·웹훅은 현재 앱 범위에 포함하지 않습니다.

`npm test`: 모의 응답으로 금액 변조, 타인 접근, 옵션/수량/동의, USD 계산, 중복 생성/승인, 금액/통화/키 불일치, 미완료 상태, 승인 응답 유실 복구, 재시작 및 만료, Origin/요청 크기/시크릿 미노출을 확인합니다.

`npm run build`: 프런트엔드 TypeScript 및 정적 빌드. `server/`와 DB, 시크릿 키는 배포 산출물 `dist/`에 포함되지 않습니다.

실제 토스 키 없이 카드 인증 성공을 검증했다고 기록하지 않습니다. 공개 화면 배포와 별도 결제 서버 활성화는 구분합니다.
